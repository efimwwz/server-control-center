**Твой Linux-сервер. Одна понятная панель мониторинга.**

Server Control Center (SCC) — самостоятельно устанавливаемая панель мониторинга Ubuntu-серверов. Она объединяет в одном интерфейсе показатели системы, Docker, Nginx, сети, служб systemd, журналы и базовые проверки безопасности.

[English](README.md) · [Русский](README.ru.md) · [Руководство по установке](INSTALL.ru.md)

## Что умеет SCC

| Раздел | Что показывает |
|---|---|
| **Система** | CPU, оперативная память, использование диска, нагрузка, время работы и сетевой трафик |
| **Docker** | Контейнеры, образы, опубликованные порты, CPU/RAM и число перезапусков |
| **Nginx** | Состояние службы, активные соединения, счётчики запросов, виртуальные хосты и история запросов |
| **Службы** | Состояние systemd, PID, использование памяти и время работы |
| **Сеть** | Интерфейсы, маршруты, шлюз, DNS, внешний IPv4, задержка и потери пакетов |
| **Журналы** | Последние выбранные события Nginx, Docker и systemd |
| **Безопасность** | Базовые проверки firewall, SSH, Fail2ban и конфигурации службы SCC в режиме чтения |
| **AI-помощник** | Необязательная диагностика через Google Gemini; без API-ключа доступен локальный диагностический механизм |

## Почему SCC

- **Самостоятельный хостинг:** панель работает на инфраструктуре, которую контролируешь ты.
- **Приватность по умолчанию:** веб-интерфейс привязан к `127.0.0.1:3000` и не публикуется установщиком на публичный сетевой интерфейс.
- **Разделение привилегий:** веб-контейнер работает без root и не получает Docker socket. Отдельный host-agent передаёт показатели через локальный Unix-сокет.
- **Мониторинг без управления:** SCC наблюдает за состоянием сервера, но не управляет контейнерами и не меняет настройки firewall, SSH или Nginx.
- **Простая установка:** готовый образ загружается из GHCR. Node.js и npm на целевом сервере не нужны.

## Локальный просмотр интерфейса

Панель можно запустить с искусственными демонстрационными данными, не подключая её к реальному серверу.

Требования: Node.js 22 и npm.

```bash
git clone https://github.com/efimwwz/server-control-center.git
cd server-control-center
npm ci
METRICS_PROVIDER=mock npm run dev
```

Открой [http://localhost:3000](http://localhost:3000). Режим mock использует синтетические данные и предназначен для локального знакомства с интерфейсом и разработки, а не для production-мониторинга.

## Установка на сервер

**Поддерживаемая платформа:** Ubuntu Server 24.04 LTS, архитектура `amd64` или `arm64`, с systemd.

Перед запуском установщика прочитай [руководство по установке](INSTALL.ru.md). В нём описаны требования, изменения системы, SSH-туннель, обратный HTTPS-прокси с авторизацией, диагностика проблем и удаление/откат.

```bash
curl -fsSL https://raw.githubusercontent.com/efimwwz/server-control-center/main/install.sh | sudo bash
```

Установщик проверяет ОС и существующие ресурсы, сверяет SHA-256 загруженного архива релиза и устанавливает соответствующую версию приложения и host-agent. Он отказывается работать на неподдерживаемых ОС и перезаписывать обнаруженные конфликтующие ресурсы SCC.

| Операционная система | Статус |
|---|---|
| Ubuntu 24.04 LTS Server, `amd64` / `arm64` | **Поддерживается** |
| Ubuntu 22.04 / 26.04 и другие версии Ubuntu | Пока не поддерживаются и не тестируются |
| Debian 12 / 13 и производные системы | Пока не поддерживаются; требуется адаптация и тестирование установщика |
| Fedora, Rocky Linux, AlmaLinux, RHEL, openSUSE, Alpine | Текущим установщиком не поддерживаются |
| Windows / Windows Server / macOS | Не поддерживаются как полноценный хост SCC: host-agent рассчитан на Linux |

Не обходи проверку ОС и не запускай внутренний установщик на неподдерживаемом дистрибутиве.

## Безопасность и приватность

SCC — панель мониторинга, а не система удалённого администрирования или авторизации.

- Веб-контейнер работает от непривилегированного пользователя и не получает Docker socket.
- Host-agent работает с правами root, поскольку читает показатели хоста. Он предоставляет фиксированные GET-эндпоинты только через локальный Unix-сокет; POST-запросы отклоняются.
- Установщик привязывает веб-панель к `127.0.0.1:3000`.
- **Встроенной страницы входа нет.** Для удалённого доступа используй SSH-туннель или обратный HTTPS-прокси с авторизацией. Не открывай порт `3000` напрямую в интернет.
- Host-agent обращается к внешним сервисам для проверки соединения и определения публичного IPv4; подробности приведены в руководстве по установке.
- Если настроен и используется Gemini, вопрос пользователя, выбранные метрики и часть последних журналов отправляются Google. Журналы могут содержать имена хостов, IP-адреса, URL и другие операционные сведения. Перед включением AI изучи раздел об обработке данных в руководстве по установке.

Порядок сообщения об уязвимостях описан в [SECURITY.md](SECURITY.md).

## Чего SCC не делает

SCC не запускает, не останавливает и не удаляет контейнеры; не меняет правила firewall, настройки SSH или Nginx; не исправляет сервер автоматически и не сканирует систему на вредоносные программы или уязвимости. Раздел безопасности содержит базовые проверки в режиме чтения и не является сертификатом безопасности.
